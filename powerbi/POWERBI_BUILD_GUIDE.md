# Power BI Build Guide

> **Why this file exists:** a `.pbix` is a proprietary binary that only Power BI
> Desktop can write, so it cannot be generated by a script. This guide plus
> `DAX/measures.dax`, `DAX/calculated_columns.dax`, `PowerQuery/power_query_m.pq`
> and `theme.json` specifies the report completely — every query, relationship,
> measure, colour and visual position. You are wiring, not designing.

Each page below is laid out on the **same grid as the previews in
`screenshots/`**, and the coordinates are given in Power BI canvas units. Set a
visual's position under **Format visual → General → Properties → Position**.
Build a page, compare it with its preview, and they should match.

---

## 0. Prerequisites

- Power BI Desktop (latest)
- Repo cloned locally, e.g. `D:\Projects\enterprise-sales-finance-analytics-dashboard\`
- The Python pipeline run so `data/processed/` is populated:

```powershell
cd D:\Projects\enterprise-sales-finance-analytics-dashboard
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python python\generate_sample_data.py
python python\clean_data.py
python python\prepare_sql_csv.py
python python\build_kpis.py
```

`prepare_sql_csv.py` is not optional here: it normalises `DimDate.csv`, and the
DimDate query expects the normalised form.

## 1. Design system

Import `theme.json` first (**View → Themes → Browse for themes**). It sets the
palette, typography and visual chrome, so nothing below needs manual colour
picking. The rules it encodes:

| Element | Value |
|---|---|
| Canvas | 1280 × 720 (16:9), page background `#F5F7FA` |
| Card surface | `#FFFFFF`, 1px `#E3E8EF` border, 3px radius, no shadow |
| Primary / navy | `#10243E` — headings, nav bar, primary series |
| Secondary / teal | `#0F7C86` — profit and comparison series |
| Categorical order | navy, teal, steel `#3E7CB1`, sage `#6FA8A5`, ochre `#C08A2E` |
| Positive / caution / negative | `#1F7A54` / `#B0791C` / `#A93226` |
| Body text / muted | `#2E3A4B` / `#6B7A8D` |
| KPI value | 24pt Segoe UI Semibold |
| Visual title | 12pt Segoe UI Semibold, left aligned |
| Axis, legend, label | 9pt Segoe UI, `#6B7A8D` |
| Table header | 9pt Segoe UI Semibold, uppercase, `#6B7A8D`, bottom rule only |
| Margin / gutter | 16px page margin, 12px between visuals |

Three rules keep the report readable, and they matter more than any individual
setting:

1. **Colour carries meaning, never decoration.** Navy is revenue, teal is
   profit, and the sentiment colours mean healthy / watch / at risk. Do not
   colour a chart by category when a single series would do.
2. **One idea per visual, stated in the title.** "Revenue and profit by month",
   not "Chart 1".
3. **Turn off what does not inform**: visual headers, drop shadows, axis
   titles that repeat the visual title, gridlines on category axes, and data
   labels on any chart that already has an axis.

## 2. Load the tables

1. **Get Data → Blank Query**.
2. **Home → Manage Parameters → New Parameter**: name `FolderPath`, type Text,
   current value `D:\Projects\enterprise-sales-finance-analytics-dashboard\data\processed\`
   (trailing backslash required).
3. For each of `DimDate`, `DimCustomer`, `DimProduct`, `DimRegion`,
   `DimInventory`, `FactSales`: create a Blank Query, open the **Advanced
   Editor**, paste the matching block from `PowerQuery/power_query_m.pq`, rename
   the query to the table name, then **Close & Apply**.

To read from SQL Server instead, point the queries at `dbo.vw_SalesFlat`,
`dbo.vw_RegionKPI`, `dbo.vw_MonthlyKPI`, `dbo.vw_InventoryRisk` and
`dbo.vw_ProductKPI` (`sql/04_views.sql`). Column names match, so the measures
work unchanged.

## 3. Build the model

Relationships — all Many-to-One, single direction:

| From | To | Notes |
|---|---|---|
| `FactSales[date_id]` | `DimDate[date_id]` | |
| `FactSales[customer_id]` | `DimCustomer[customer_id]` | |
| `FactSales[product_id]` | `DimProduct[product_id]` | |
| `DimCustomer[region_id]` | `DimRegion[region_id]` | |
| `DimInventory[product_id]` | `DimProduct[product_id]` | |
| `DimCustomer[signup_date]` | `DimDate[full_date]` | **Mark Inactive** — used by `New Customers` through `USERELATIONSHIP` |

Then:

- Select `DimDate` → **Table tools → Mark as Date Table** → column `full_date`.
- Hide from report view: every `*_id` key except where a visual needs it,
  `FactSales[date_id]`, and `DimDate[date_id]`.
- Set `DimDate[Month-Year]` to **Sort by column** `Month-Year Sort`, and
  `DimDate[Quarter Label]` by `Quarter Sort`. Without this, every date axis
  sorts alphabetically.

**`DimRegion` is at country grain.** `region_name` repeats — three rows are
"Asia Pacific". Group region-level visuals on `region_name`, and use `country`
only as the level beneath it. See `docs/KPI_DEFINITIONS.md`.

## 4. Add the DAX

- Select **FactSales → Modeling → New Measure** and paste each measure from
  `DAX/measures.dax` (each `Name = ...` block is one measure).
- Add the calculated columns from `DAX/calculated_columns.dax` to the tables
  named in the headings. `DimDate[Month Index]` is required by the trend
  measures — add it before `Linear Trend Revenue`.
- Set the format strings noted in the comments (Measure tools → Format).
  Currency with 0 decimals, percentages with 1, growth measures with an
  explicit sign.
- Group the measures into a display folder `_KPI Measures` (select all →
  Properties → Display folder).

## 5. Page chrome (build once, copy to all six pages)

Set page size to **1280 × 720** (Format page → Canvas settings → Type: 16:9).

**Navigation bar** — y 0, height 44, full width, `#10243E` rectangle.
- Report title textbox at x 16, 14pt Segoe UI Semibold, white.
- Six **Insert → Buttons → Blank** buttons starting at x 420, height 26, y 9,
  spaced 4px, one per page, **Action → Type: Page navigation**. Text 11.5pt;
  active page white on a 14%-white fill, inactive `#9FB3C8` on transparent.

**Filter strip** — y 44, height 30, full width, white with a `#E3E8EF` bottom
rule. Put the four slicers here, or a textbox bound to the `Filter Context
Title` measure so the strip states the current selection in words.

**Content area** — x 16 to 1264, starting at y 90. 12px between visuals.

Build the bar and strip on the Executive Dashboard, select all of it, copy, and
paste onto each other page so the chrome sits in identical positions — that is
what makes page switching feel like one product rather than six reports.

## 6. Pages

Each page states the question it answers. If a visual does not help answer it,
it belongs on another page.

### 6.1 Executive Dashboard — "How is the business performing?"

| Visual | Position (x, y, w, h) | Fields |
|---|---|---|
| KPI card × 6 | y 90, h 78, w 198, from x 16 step 210 | Total Revenue · Total Profit · Profit Margin % · Revenue YoY % · Total Orders · Total Customers |
| Line chart | 16, 180, 780, 248 | Axis `DimDate[Month-Year]`; values `Total Revenue` (navy), `Total Profit` (teal) |
| Bar chart | 808, 180, 456, 248 | Axis `DimRegion[region_name]`; value `Total Revenue` |
| Bar chart | 16, 440, 400, 264 | Axis `DimProduct[product_name]`, Top 5 by `Total Revenue` |
| Bar chart | 428, 440, 400, 264 | Axis `DimProduct[category]`; value `Total Revenue` |
| Insights panel | 840, 440, 424, 264 | See below |

KPI card order is the hierarchy: outcome (revenue, profit, margin), then
direction (growth), then volume (orders, customers). Give the growth card a
`Growth Colour` conditional format so the sign is legible at a glance.

The **insights panel** is a card with three findings, each a short bold
headline and one line of supporting numbers. Take the wording from
`reports/executive_insights.md`, which derives it from the KPI tables — do not
hand-write claims into the report. A textbox bound to measures keeps it live;
a static textbox refreshed when the pipeline runs is acceptable if you note the
as-of date.

### 6.3 Financial Analytics — "Are we growing profitably?"

| Visual | Position | Fields |
|---|---|---|
| KPI card × 6 | y 90, h 78, w 198 | Total Revenue · Total Cost · Total Profit · Profit Margin % · lowest category margin · count of products below 35% |
| Line chart | 16, 180, 780, 248 | `Total Profit` by `DimDate[Month-Year]`; note the monthly margin range in the subtitle |
| Bar chart | 808, 180, 456, 248 | Axis `DimProduct[category]`; value `Profit Margin %`; conditional colour from `Margin Status Colour` |
| Table | 16, 440, 620, 264 | Lowest-margin products with a `Margin Status` column, conditionally formatted |
| Bar chart | 648, 440, 616, 264 | Axis `DimRegion[region_name]`; value `Total Profit` (teal) |

Keep profit and margin on **separate visuals**, or on a combo chart with an
explicit secondary axis. A currency series and a percentage series plotted
against one axis is the most common way to make a finance page lie.

### 6.4 Customer Analytics — "Who are our customers and how are they behaving?"

| Visual | Position | Fields |
|---|---|---|
| KPI card × 6 | y 90, h 78, w 198 | Total Customers · customers on file · Orders Per Customer · Revenue Per Customer · Repeat Customer Rate · Average Order Value |
| Line chart | 16, 180, 780, 248 | `Cumulative Customers` by signup month |
| Donut | 808, 180, 456, 248 | Legend `DimCustomer[segment]`; value `Total Revenue` |
| Table | 16, 440, 700, 264 | Top 10 customers: name, segment, region, revenue, orders, AOV |
| Bar chart | 728, 440, 536, 264 | Axis `DimCustomer[segment]`; value `Revenue Per Customer` |

Use `DimCustomer[Customer Tier]` as a drill level on the donut, or as an extra
slicer, rather than a second pie of the same revenue.

Note in the page tooltip that `Repeat Customer Rate` reads 100% on this
dataset and why (`docs/KPI_DEFINITIONS.md`). Showing a saturated metric without
that context invites a wrong conclusion.

### 6.5 Inventory Analytics — "Where are we exposed to inventory risk?"

| Visual | Position | Fields |
|---|---|---|
| KPI card × 6 | y 90, h 78, w 198 | stock positions · Total Stock On Hand · Stock Value · Inventory Turnover Ratio · Products Needing Reorder (red) · Products At Risk (amber) |
| Clustered bar | 16, 180, 660, 300 | Axis `DimProduct[product_name]` sorted ascending by `DimInventory[Stock vs Reorder]`; values stock on hand and reorder level |
| Bar chart | 688, 180, 576, 300 | Turnover ratio by product, descending |
| Table | 16, 492, 1248, 212 | Watchlist filtered to `Risk Flag <> "OK"`: product, category, warehouse, stock, reorder level, headroom, stock value, status |

Sort the stock chart by **headroom, ascending** — the products closest to the
trigger belong at the top. Sorting alphabetically buries the risk.

### 6.6 Forecast Dashboard — "What is likely to happen next?"

| Visual | Position | Fields |
|---|---|---|
| KPI card × 6 | y 90, h 78, w 198 | last actual month · next month projected · 6-month projection · modelled range · vs same months last year · `Revenue Trend Slope` per month |
| Line chart | 16, 180, 1248, 330 | `Total Revenue` (solid navy), `Revenue 3M Moving Avg` (sage), `Linear Trend Revenue` (dashed ochre), plus **Analytics → Forecast**: 6 periods, 95% confidence, seasonality 12 |
| Table | 16, 522, 700, 182 | Six projected months with low / projected / high / trend |
| Method panel | 728, 522, 536, 182 | Textbox: method, what the range is, what it assumes |

Three requirements on this page, in order of importance:

1. **Actuals and projection must be visually distinct.** Solid line for
   recorded revenue, dashed for the projection, shaded band for the range.
2. **Mark where the actuals stop.** A dashed vertical rule labelled "Last
   actual" at the final recorded month.
3. **State the method and its assumptions on the page**, not in a footnote.
   The method panel is not optional decoration — a forecast presented without
   its assumptions is a claim, not an analysis.

Never label the projection "expected revenue" or a target.

## 7. Interactivity

**Synced slicers** — Year (`DimDate[year]`), Region (`DimRegion[region_name]`),
Category (`DimProduct[category]`), Segment (`DimCustomer[segment]`), in the
filter strip. **View → Sync slicers**, tick Sync and Visible for all six pages.
Use dropdown style so the strip stays 30px tall.

**Bookmarks** (**View → Bookmarks → Add**) — one per preset: "Current year",
"Prior year", "All time", "Reset filters". Set each to capture *data* only, not
display, so a bookmark does not drag the user to another page. Wire them to
buttons with **Action → Type: Bookmark**.

**Drill-through** — add a page `Product Detail`, put `DimProduct[product_id]`
in the **Drillthrough** filter well, and place monthly revenue, margin trend,
top customers and stock position for the selected product. Keep the back button
Power BI adds. Any product visual then supports right-click → Drill through.

**Tooltips** — create a page, set **Page information → Allow use as tooltip**
and **Canvas settings → Type: Tooltip**, and put three compact figures on it
(revenue, profit, margin). Assign it under each chart's **Format visual →
Tooltips → Type: Report page**. Do not repeat what the axis already shows.

**Interactions** — **Format → Edit interactions**: set the KPI cards not to be
filtered by chart selections, so the headline figures stay stable while the
user explores.

---

## 8. Accessibility and finish

- Check every text/background pair against 4.5:1 contrast. The palette above
  passes; a lighter navy would not.
- Never encode a status by colour alone — the watchlist carries a text status
  column beside the colour.
- Set **Alt text** on each visual (Format visual → General → Alt text).
- Set the tab order under **View → Selection → Tab order**: KPI cards first,
  then visuals left to right.
- Turn on **Format page → Canvas settings → Vertical alignment: Top** so pages
  do not drift when the window resizes.

## 9. Save and publish

Save as `powerbi/Enterprise_Sales_Finance_Dashboard.pbix`. `.gitattributes`
already tracks `*.pbix` through Git LFS — run `git lfs install` once before the
first commit.

Export each page (**File → Export → PDF**, or a screen capture at 1280×720)
into `screenshots/` if you want real captures alongside the generated previews.
Keep the generated SVGs: they regenerate from the data and stay accurate when
the pipeline is re-run.
